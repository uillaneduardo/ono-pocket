Fluxos & comportamento

Esta página documenta como as telas se conectam, quais estados mudam durante uma ação e quais regras pertencem ao frontend ou ao backend. A referência visual canônica das telas está no Stitch Screenbook.

Separação de responsabilidades: o Screenbook documenta aparência; esta página documenta sequência, transições, estados e autoridade do sistema.

Fluxos principais

Viagem

Mapa → Destino → Confirmar → Em trânsito → Chegada.

O cliente apresenta estimativa e progresso. O servidor valida início, finishes_at e conclusão.

Trabalho

Local → Trabalho → Selecionar Ono → Confirmar → Em andamento → Resultado.

Disponibilidade, energia, requisitos e recompensa são validados pelo backend.

Inventário

Inventário → Item → Context Sheet → Ação.

Usar, vender, transferir ou analisar sempre gera operação validada pelo servidor.

Ono

Menu → Onos → Lista → Detalhe → Ação compatível.

Estado, energia, Vínculo e ocupação devem estar visíveis antes de qualquer ação.

Autoridade do sistema

Frontend

Renderiza estado, navegação, feedback, loading, sheets e estimativas.

Backend

Autoridade para timers, inventário, energia, créditos, OPP, mercado, recompensas e geração de recursos.

Persistência

A UI nunca conclui uma ação por conta própria; ela reflete timestamps e resultados persistidos.

Referência visual

Para aparência, composição, ícones, imagens e navegação das telas, use o Stitch Screenbook. Evite criar uma segunda versão visual nesta página.
